# Requirements Document — xnuxuz — Personal Life OS

**Versi:** 1.1 — Draft matang untuk development
**Owner:** Adam
**Budget infra:** Rp1.500.000 / tahun
**Prinsip:** API-first, single VPS, free-tier services, build from scratch, monorepo (moon) + Biome

---

## 1. Visi Produk

Personal assistant system yang meng-cover tiga domain hidup dalam satu ekosistem:

1. **Schedule & Assistant** — manajemen jadwal, event, reminder, daily briefing
2. **Grinding & Productivity** — task management, session tracking, streak, goals
3. **Finance** — pencatatan pemasukan/pengeluaran, budget, cashflow report

Semua diakses lewat multi-channel (Telegram sebagai channel utama, web dashboard, mobile app, email, WhatsApp opsional) dengan AI layer yang paham konteks personal user lewat structured memory + RAG.

Target awal: single user (Adam). Arsitektur disiapkan multi-user agar bisa dijadikan SaaS di masa depan tanpa refactor besar.

## 2. Arsitektur Sistem

```
┌────────────────────────────────────────────────────────┐
│ CLIENTS                                                │
│  Next.js Web  │  Mobile (Expo/RN)  │  Telegram  │  WA  │
└───────────────────────┬────────────────────────────────┘
                        │ HTTPS (REST /api/v1)
              ┌─────────▼──────────┐
              │   Express API      │  ← single source of truth
              │   + Auth (JWT)     │
              └─────────┬──────────┘
        ┌───────────┬───┴──────┬──────────────┐
        │           │          │              │
   ┌────▼───┐  ┌────▼────┐ ┌───▼────────┐ ┌──▼─────────┐
   │ MySQL  │  │ Redis   │ │ AI Layer   │ │ Integrasi  │
   │ (main) │  │ Stack   │ │ Groq/      │ │ GCal,      │
   │        │  │ +BullMQ │ │ Gemini     │ │ Notion,    │
   │        │  │ +Vector │ │            │ │ Email      │
   └────────┘  └─────────┘ └────────────┘ └────────────┘
```

**Aturan arsitektur:**
- Semua client (bot, web, mobile) hanya konsumsi API — zero business logic di client/bot handler
- API versioning dari hari pertama: `/api/v1/`
- Notification dispatch lewat satu abstraction (`NotificationService`) dengan adapter per channel
- Background job (reminder, recurring, memory extraction, digest) semua lewat BullMQ

## 3. Functional Requirements

Prioritas pakai MoSCoW: **[M]** Must have (MVP), **[S]** Should have, **[C]** Could have, **[W]** Won't have (fase awal).

### 3.1 Auth & User

- [M] Register/login email + password (argon2/bcrypt hash)
- [M] JWT access token (15 menit) + refresh token (rotasi, disimpan di Redis)
- [M] Link akun Telegram via one-time code (`/link ABC123` di bot)
- [S] Device management: list & revoke session per device (penting saat mobile masuk)
- [C] OAuth Google login
- [W] Multi-tenant billing

### 3.2 Schedule & Assistant Module

- [M] CRUD event (judul, waktu mulai/selesai, lokasi, kategori, notes)
- [M] Recurring event dengan format RRULE (kompatibel Google Calendar)
- [M] Reminder per event: offset custom ("30 menit sebelum") + default per kategori
- [M] Daily briefing pagi (jam configurable) via Telegram: jadwal hari ini, task priority, sisa budget harian
- [S] Nightly review otomatis: apa yang selesai, apa yang miss, streak update
- [S] Conflict detection saat create event yang bentrok
- [S] Google Calendar sync dua arah (OAuth2, scope `calendar.events`)
- [C] Timeblocking suggestion by AI berdasarkan pola produktif user
- [C] Notion sync untuk notes/knowledge base

### 3.3 Grinding / Productivity Module

- [M] CRUD task: judul, deskripsi, kategori (kuliah, HME, Meterin, side project, dll — user-defined), priority, deadline, status
- [M] Recurring task
- [M] Session logging: start/stop timer atau manual entry (durasi, kategori, task terkait)
- [M] Streak tracking per kategori + global
- [S] Goal system: target jam mingguan per kategori, progress bar
- [S] Statistik: heatmap kontribusi (ala GitHub), breakdown jam per kategori per minggu
- [S] Weekly review auto-generated by AI (ringkasan pencapaian + saran)
- [C] Pomodoro mode di mobile/web
- [C] Subtask & task dependency

### 3.4 Finance Module

- [M] Account management: cash, rekening bank, e-wallet (saldo per account)
- [M] Transaction ledger: income/expense/transfer antar-account, kategori, tanggal, notes, account_id
- [M] Money disimpan sebagai INTEGER rupiah (BUKAN float)
- [M] Quick entry via chat: "keluar 25rb makan siang gofood" → AI parse → konfirmasi → insert
- [M] Budget bulanan per kategori + alert Telegram saat 80% dan 100% terpakai
- [M] Recurring transaction (kos, langganan) auto-insert via scheduled job
- [S] Cashflow report: bulanan in/out, trend 6 bulan, breakdown per kategori
- [S] Soft delete + audit trail transaksi
- [S] Export CSV/Excel
- [C] Attachment struk (foto) — storage lokal VPS
- [C] Split transaction (satu nota banyak kategori)
- [W] Bank sync otomatis / scraping (risiko & maintenance tinggi)

### 3.5 AI Assistant Layer

- [M] Intent router: satu endpoint natural language → classify intent → function call
  - Function schema minimal: `createTask`, `createEvent`, `createTransaction`, `getSchedule`, `getBalance`, `getSpendingReport`, `getTasks`, `logSession`
- [M] Context assembler per request:
  1. `user_facts` (structured memory, MySQL)
  2. Konteks hari ini (jadwal, task pending, saldo, streak)
  3. Correction rules (deterministic overrides)
  4. RAG retrieval (fase 2)
- [M] Konfirmasi sebelum write action dari AI (inline button Telegram: ✅ / ✏️ / ❌)
- [S] Memory extraction pipeline (background job): ekstrak fakta baru dari percakapan → upsert `user_facts`
- [S] Feedback loop: 👍👎 per AI action → tabel `ai_feedback`; koreksi kategori jadi rule permanen
- [S] RAG episodic memory: summary per sesi percakapan → embed (Gemini `text-embedding-004` atau bge-m3) → Redis vector search → hybrid retrieval (vector + filter temporal/kategori)
- [C] Behavior pattern mining: aggregation query mingguan atas session/transaction → auto-generate facts ("user produktif malam hari")
- [C] Proactive suggestion (AI inisiatif ingetin, bukan cuma reaktif)

### 3.6 Notification Service

- [M] Abstraction layer: `NotificationService.send(userId, payload, { channels, priority })`
- [M] Adapter Telegram (utama)
- [M] Adapter Email — Nodemailer + Gmail app password, atau Resend free (3.000/bln)
- [S] Adapter Push (Expo Push / FCM) — saat mobile masuk
- [S] Preference per user per jenis notifikasi (reminder → Telegram, digest → email, dst.)
- [S] Idempotency: BullMQ job ID unik per (task_id + waktu) agar reminder tidak double-fire
- [C] Adapter WhatsApp — Baileys (personal use) dengan fallback ke Telegram; migrasi ke WA Cloud API jika serius
- [C] Quiet hours (jangan notif jam tidur, kecuali priority high)

## 5. Non-Functional Requirements

### 5.1 Infrastruktur (Budget Rp1,5jt/tahun)

| Komponen | Pilihan | Biaya/tahun |
|---|---|---|
| VPS | Contabo VPS (4 vCPU/8GB, ~US$5,5/bln) ATAU IDCloudHost/Biznet Gio 2vCPU/4GB (latency ID lebih baik) | Rp1.100.000–1.200.000 |
| Domain | `.my.id` (Rp±15rb) atau `.com` (Rp±180rb) | Rp15.000–180.000 |
| SSL | Let's Encrypt (auto via Caddy) | Rp0 |
| LLM | Groq (Llama 3.3 70B) + Gemini Flash free tier | Rp0 |
| Embedding | Gemini `text-embedding-004` free tier | Rp0 |
| Telegram Bot API | — | Rp0 |
| Google Calendar API, Notion API | — | Rp0 |
| Email | Gmail app password / Resend free | Rp0 |
| Push | Expo Push / FCM | Rp0 |
| **Total** | | **±Rp1,2jt — sisa buffer ±Rp300rb** |

**Deployment di satu VPS via Docker Compose:**
- Container: `mysql:8`, `redis/redis-stack` (RediSearch untuk vector), `api` (Express), `web` (Next.js), `worker` (BullMQ consumer + bot polling)
- Reverse proxy: **Caddy** (auto-SSL, config minimal)
- Telegram pakai **long polling** (bukan webhook) → tidak butuh endpoint publik untuk bot, lebih simpel
- RAM budget kasar: MySQL ±500MB, Redis Stack ±300MB, Node processes ±600MB → 4GB aman, 8GB nyaman
- JANGAN self-host Ollama di VPS ini — tetap pakai Groq/Gemini

### 5.2 Data & Keamanan

- Password: argon2id
- Refresh token: rotasi + revocation list di Redis
- Rate limiting di API (express-rate-limit + Redis store)
- Semua timestamp UTC di DB, konversi timezone (`Asia/Jakarta`) di edge/client
- Backup MySQL: `mysqldump` harian via cron → simpan 7 hari lokal + upload mingguan ke Google Drive (API gratis) — **data finance tidak boleh hilang**
- Secrets di `.env`, tidak pernah masuk git
- Finance endpoint butuh auth penuh; pertimbangkan re-auth untuk delete/export

### 5.3 Reliability & Ops

- Health check endpoint + uptime monitor gratis (UptimeRobot / Better Stack free) → alert ke Telegram
- Logging: pino + rotasi file; error kritis dikirim ke Telegram channel pribadi
- BullMQ dashboard (bull-board) di route ter-auth untuk inspeksi job
- Graceful degradation: jika LLM down/limit, quick entry fallback ke parser regex sederhana ("keluar {angka}{rb/jt} {teks}")
- Rate limit AI: cache respons di Redis; digest digenerate 1x/hari, bukan per-request

### 5.4 Skalabilitas (Future-proofing SaaS)

- Semua tabel punya `user_id` dari hari pertama
- Monolith modular: satu codebase Express, folder per module (`/modules/schedule`, `/modules/finance`, dst.) — JANGAN microservices untuk skala ini
- Notification adapter pattern → tambah channel tanpa sentuh module lain

  │   └── mobile/             # Expo app, fase 2 (@xnuxuz/mobile)

- [M] moon tasks standar per project: `build`, `dev`, `lint`, `format`, `check`, `typecheck`, `test`

- [S] Toolchain pinning di `.moon/toolchain.yml` (versi Node konsisten di semua mesin — laptop, VPS, CI)

**Linting & formatting dengan [Biome](https://biomejs.dev):**

- [M] Biome sebagai satu-satunya linter + formatter (pengganti ESLint + Prettier sekaligus) — satu config `biome.json` di root, berlaku semua workspace
- [M] Pre-commit hook (lefthook/husky): `biome check --write --staged`
- [M] CI gate: `moon run :lint` harus pass sebelum merge

- Catatan: Biome belum cover semua plugin ESLint (misal eslint-plugin-security) — untuk skala project ini itu acceptable trade-off demi kecepatan (Biome ~25x lebih cepat, Rust-based) dan zero-config-fatigue

## 8. Risiko & Mitigasi

| Risiko | Dampak | Mitigasi |
|---|---|---|
| Free tier LLM berubah/limit turun | AI layer mati | Abstraction LLM provider (satu interface, ganti Groq↔Gemini via env); fallback regex parser |
| Baileys/WA unofficial kena ban | Channel WA mati | WA = channel opsional; Telegram tetap primary |
| VPS single point of failure | Semua mati | Backup harian + dokumentasi restore; Docker Compose = redeploy < 30 menit |
| Scope creep (7 modul sekaligus) | Tidak pernah selesai | Roadmap fase ketat; fase n+1 baru mulai setelah fase n dipakai harian |
| Data finance corrupt/hilang | Kepercayaan pada sistem hancur | Integer money, soft delete, audit trail, backup off-site mingguan |
| Free tier email limit | Digest tidak terkirim | Digest 1x/hari saja (30/bulan — jauh di bawah limit semua provider) |
